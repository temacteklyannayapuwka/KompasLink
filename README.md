# KompasLink

Диагностический прототип Windows-утилиты для работы с внешними файловыми ссылками КОМПАС-3D. Целевая версия — v18; совместимость с её SDK и установленной системой пока не подтверждена.

Русскоязычное окно показывает подключение, версию КОМПАС, путь активного документа, признаки изменения и режима только для чтения. Кнопка «Обновить диагностику» запускает чтение, область результатов показывает сообщения и ошибки текущего запуска.

Адаптер подключается к уже запущенному КОМПАС через `KOMPAS.Application.5`, запрашивает версию через `ksGetSystemVersion`, получает API 7 методом `ksGetApplication7` и читает активный документ. Названия методов проверены по официальной онлайн-справке более новых SDK; это не является подтверждением наличия и сигнатур в v18.

## Требования

- Windows и установленный КОМПАС-3D с зарегистрированным COM API.
- Один запущенный экземпляр КОМПАС, одинаковый пользователь и уровень прав с утилитой.
- Для первого испытания — локальная тестовая копия `.a3d` или `.m3d`.
- Для сборки — Go 1.23 или новее, доступ к зависимостям из `go.mod`, включая Walk и go-ole. CGo и C-компилятор не требуются.
- Для запуска собранного EXE Go и браузерный движок не требуются. Рядом с `kompaslink.exe` должен находиться `kompaslink.exe.manifest` для Common Controls 6.

## Сборка

PowerShell, из каталога проекта, для первоначального испытания на Windows x64 и КОМПАС x64:

```powershell
.\build.ps1
```

Для испытания с 32-разрядной установкой: `.\build.ps1 -Architecture 386`. Межразрядное подключение здесь не проверено. Скрипт собирает окно, консольную диагностику и копирует manifest; запускать окно следует только после успешного завершения скрипта. Политика выполнения PowerShell должна разрешать запуск локального скрипта.

## Запуск

Откройте тестовый документ в КОМПАС, запустите `bin/kompaslink.exe` двойным щелчком и нажмите «Обновить диагностику». Окно также можно открыть из PowerShell:

```powershell
.\bin\kompaslink.exe
```

Окно не запускает КОМПАС автоматически. При отсутствии приложения или документа объяснение появится в результатах. Поля очищаются перед каждым чтением, чтобы старые сведения не выглядели актуальными после ошибки. После переключения документа в КОМПАС нажмите обновление снова. Сообщения хранятся только в памяти текущего запуска.

Консольная диагностика сохранена отдельно. Для получения JSON-отчёта:

```powershell
.\bin\kompaslink-diag.exe | Out-File -Encoding utf8 diagnostic.json
$LASTEXITCODE
```

Результат — JSON с полями `report` и, при ошибке, `error`. Код завершения 1 означает ошибку подключения или чтения; 0 — завершённое чтение, в том числе при отсутствии активного документа. Состояние `document_observed` означает только получение сведений и не разрешает редактирование.

`no_active_document` — документа нет; `document_without_saved_path` — API не сообщил абсолютный путь и каталог; `document_has_unsaved_changes` — КОМПАС сообщил несохранённые изменения. `has_saved_path` не доказывает наличие файла на диске. `type_id` оставлен числом до проверки перечислений SDK v18.

## Ограничения

Внешние ссылки не читаются и не заменяются. Резервное копирование и сохранение CAD-документов отсутствуют. Не вызываются создание экземпляра КОМПАС, открытие или закрытие документов, сохранение и `Quit`. SQL-база ЛОЦМАН не используется.

Все COM-операции одного запроса, включая освобождение объектов, выполняются синхронно в STA на закреплённом потоке ОС. В окне запрос выполняется в отдельной goroutine; интерфейс получает через очередь Walk только обычные Go-значения, после освобождения COM-объектов. Элементы окна обновляются только его потоком. При ошибке обязательного свойства диагностика прекращается, неизвестные значения не принимаются за `false`.

Подключение через ROT не выбирает экземпляр по PID. При нескольких установках или процессах выбранный COM-сервер может отличаться от ожидаемого; проверяйте полученную версию. Прототип не содержит подписок на события, фонового COM-цикла, автоматических повторов и гарантированного тайм-аута зависшего COM-вызова.

Во время чтения повторный запуск и обычное закрытие окна заблокированы до освобождения COM-объектов. При зависшем вызове окно продолжит обрабатывать сообщения, но закончить чтение или безопасно отменить его по тайм-ауту прототип не умеет.

Запуск и визуальная проверка окна на Windows, а также интеграция с реальным КОМПАС-18 пока не проведены. Сведения об исследовании и ручной проверке — в [docs/API-EVIDENCE.md](docs/API-EVIDENCE.md).
