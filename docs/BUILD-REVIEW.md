# Проверка сборки KompasLink

Дата: 22 октября 2026 года. Проверялся диагностический прототип на основе исходников `b1a60e2346438d93610b567b76237a7046627459` с изменениями сборки и зависимости, описанными ниже.

## Границы проверки

Просмотрены собственные Go-исходники, manifest и скрипт сборки. В них не обнаружены загрузка исполняемых файлов, запуск сторонних процессов, установка автозапуска, отключение защиты или изменение CAD-файлов. Адаптер получает существующий COM-объект и читает сведения о версии и активном документе. Интерфейс использует нативные Windows-контролы Walk.

Проверены версии и целостность модулей. Выборочно просмотрены COM-вызовы go-ole и загрузка системных DLL, а также использование процессов и сети в зависимостях интерфейса. Это ограниченное ревью, не полный аудит всех зависимостей, компилятора и ОС и не гарантия отсутствия вредоносного кода.

Удалённый антивирусом EXE с компьютера предприятия здесь не получен и не исследован. Его совпадение с исходниками не установлено. Новый EXE не является тем же образцом и не объясняет автоматически старое срабатывание.

## Изменения

Версия компилятора закреплена: Go 1.27.3. Скрипт отвергает другую версию, задаёт целевую архитектуру и стандартные настройки процессора, отключает CGo, внешнее рабочее пространство и дополнительные флаги Go. Контрольные суммы и сведения о модулях записываются рядом с результатами. Доступность компилятора: [официальные загрузки Go](https://go.dev/dl/).

`golang.org/x/sys` обновлён с v0.1.0 до v0.44.0 из-за [GO-2026-5024](https://pkg.go.dev/vuln/GO-2026-5024). Первичный govulncheck обнаружил уязвимость на уровне импортируемого пакета, но не обнаружил затронутых вызовов приложения. Исправленная зависимость требует языка Go 1.25.0; компилятор сборки остаётся 1.27.3. Остальные версии зависимостей не изменены.

Флаги `-trimpath -buildvcs=false -mod=readonly` используются для повторяемости и контроля зависимостей. Упаковка, обфускация, удаление отладочных сведений и изменения для обхода антивируса не применяются. EXE не подписан.

## Проверки

Проверки выполняются на Linux с кросс-компиляцией для Windows, а не на компьютере с КОМПАС. Результаты не подтверждают работоспособность интерфейса или интеграции на Windows.

Команды проверки зависимостей и статического анализа:

```text
go mod verify
go vet ./...
govulncheck ./...
```

Для Windows задаются `GOOS=windows`, `CGO_ENABLED=0`, `GOARCH=amd64` или `386`. Используется govulncheck v1.9.0. Проверка известных уязвимостей не является антивирусным анализом.

Результаты после обновления зависимости:

| Проверка | Результат |
| --- | --- |
| `go mod verify` | Все модули проверены |
| `go vet`, Windows amd64 и 386 | Без замечаний |
| Сборка GUI и CLI, Windows amd64 и 386 | Успешно |
| `govulncheck`, Windows amd64 | `No vulnerabilities found` |
| Повторная полная сборка amd64 с `-a` | Оба EXE побайтно совпали с первой сборкой в этой среде |
| Запуск на Windows, PowerShell, КОМПАС-18, Kaspersky | Не проверено |

SHA256 полученных amd64-образцов:

```text
c62f18ebea0cb2003c7347ef043da7d9fd4b7f381b26979c54faedb94ebd036f  kompaslink.exe
860b324b6f2dd597e88f457d120929ca290a6bbb9580e32fff62ecc22919d012  kompaslink-diag.exe
```

Это идентификаторы новых образцов для анализа, не сертификат безопасности и не хеши удалённого файла с предприятия. Повторяемость на другом хосте отдельно не проверялась.

PowerShell-скрипт в этой среде не исполнялся: PowerShell отсутствует. Проверяется эквивалентная последовательность Go-команд; совместимость самого скрипта требует проверки на Windows. Реальный КОМПАС-18, его SDK и движок Kaspersky здесь недоступны.

## Разбор срабатывания Kaspersky

На предоставленных снимках Kaspersky Endpoint Security сообщил `VHO:Trojan.Win32.Convagent.gen`, эвристический анализ, и удаление `kompaslink.exe`. Эвристическое срабатывание само по себе не подтверждает ни наличие трояна, ни ложный результат.

1. Прекратить запуски и повторные сборки на производственном ПК. Не отключать защиту, не добавлять исключения и не восстанавливать объект для запуска.
2. Передать администратору ИБ отчёт события, точный SHA256 из отчёта, версию Kaspersky и время обновления баз. Уже сохранённые снимки можно использовать как дополнение; не нужно добиваться повторного удаления файла.
3. Администратору организовать получение исходного образца из резервного хранилища по правилам предприятия, без его запуска. Если это невозможно, явно указать, что исходный образец недоступен. Новый образец собирать в согласованной изолированной среде, не меняя защиту рабочего ПК.
4. Передать образец, контрольные суммы, сведения о сборке и ссылку на исходники в поддержку Kaspersky через CompanyAccount. При допустимости по политике предприятия использовать OpenTIP и запрос повторного анализа. Не загружать CAD-документы, корпоративные данные или секреты.
5. Дождаться разбора и согласования ИБ перед возобновлением испытаний. Отсутствие результата поиска по хешу не означает, что файл безопасен.

Это соответствует [официальной процедуре Kaspersky](https://support.kaspersky.com/common/error/other/15332). Обращение в поддержку из этого проекта автоматически не отправляется.

Для обращения нужны: назначение программы (локальная Windows-диагностика КОМПАС через COM), источник (этот репозиторий и точный коммит), обнаружение и причина запроса (проверка возможного ложного срабатывания), точный образец и его SHA256. Не заявляйте, что ложное срабатывание уже доказано.
