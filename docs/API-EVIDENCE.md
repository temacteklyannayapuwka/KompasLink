# Основания и границы совместимости

Исследование: 21 октября 2026 года. Локальный SDK КОМПАС-18 не предоставлен. Доступную онлайн-документацию новых выпусков нельзя считать доказательством наличия интерфейса в v18. Прототип является кандидатом для проверки, а не подтверждённым адаптером v18.

## Использованные первичные источники

- [KompasObject::ksGetSystemVersion](https://help.ascon.ru/KOMPAS_SDK/24/ru-RU/kompasobject_ksgetsystemversion.html): Automation возвращает LONG, принимает четыре выходных LONG*, успех — 1.
- [KompasObject::ksGetApplication7](https://help.ascon.ru/KOMPAS_SDK/22/ru-RU/kompasobject_ksgetapplication7.html): возвращает IDispatch приложения API 7.
- [IApplication::ActiveDocument](https://help.ascon.ru/KOMPAS_SDK/22/ru-RU/iapplication_activedocument.html): активный IKompasDocument.
- [Свойства IKompasDocument](https://help.ascon.ru/KOMPAS_SDK/22/ru-RU/ikompasdocument_props.html): Name, Path, PathName, DocumentType, Changed, ReadOnly.
- [PathName](https://help.ascon.ru/KOMPAS_SDK/22/ru-RU/ikompasdocument_pathname.html): полное имя документа.
- [ReplaceExternalFilesNames](https://help.ascon.ru/KOMPAS_SDK/22/ru-RU/ikompasdocument1_replaceexternalfilesnames.html): пометка «Компас v20»; параметр allFiles допускает рекурсию. В прототипе отсутствует.
- [IApplication::GetSystemVersion](https://help.ascon.ru/KOMPAS_SDK/22/ru-RU/iapplication_getsystemversion.html): пометка v22. Не используется; не следует путать с методом API 5.
- [Walk](https://github.com/lxn/walk): нативный Windows GUI; manifest Common Controls 6 обязателен, CGo-цикл необязателен. GUI-зависимости в прототип не включены.
- [go-ole v1.3.0](https://github.com/go-ole/go-ole/tree/v1.3.0): подключение через GetActiveObject, late binding IDispatch; исходники скачанного модуля проверены для выходных *int32 и владения VARIANT.

Наличие ProgID, методов и сигнатур необходимо сверить с библиотеками типов конкретной v18. Название `.5` / `.7` обозначает поколение API, а не выпуск КОМПАС.

Это неизвестные, а не объявление всех типов неподдерживаемыми. До получения SDK не заявляется ни полнота перечисления, ни возможность редактирования. Методы и свойства отдельных типов будут приниматься только после проверки сигнатур, правил сохранения и испытаний на копиях.

Правила относительных и системных путей v18 не установлены. Нельзя разрешать их относительно рабочего каталога утилиты по умолчанию. Для будущей проверки файлов нужны отдельные исходный адрес, разрешённый путь и основание разрешения. Нефайловые адреса не следует отправлять в os.Stat.

## Что требуется от целевой установки

- Версия Windows и её разрядность; полная версия, сборка и разрядность КОМПАС; каталог установки; какие другие версии установлены.
- Дерево каталога SDK, поставленного именно с этой версией.
- CHM/HTML-справка SDK, файлы TLB (в том числе Kompas6API5.tlb, KompasAPI7.tlb, если они присутствуют), константы, IDL и заголовки описаний интерфейсов. Фактические имена сверить по дереву SDK.
- Примеры подключения и работы со сборками/внешними ссылками из того же SDK.
- Небольшая разрешённая к передаче тестовая сборка с деталью: исходная и скопированная папки; позднее — отдельные примеры переменных и внешней геометрии. Производственные модели не требуются.

## Ручная проверка на Windows

Перед проверкой сопоставить сигнатуры с SDK v18. Пока это не сделано, запуск остаётся экспериментальной диагностикой.

1. При закрытом КОМПАС: JSON с ошибкой, код 1, новый процесс КОМПАС не появляется.
2. При одном запущенном КОМПАС без документов: версия соответствует «О программе», документа нет, код 0.
3. При активной сохранённой тестовой .m3d: имя, каталог, полный путь, числовой тип и признаки совпадают с состоянием КОМПАС.
4. Повторить для .a3d. Проверить кириллицу и пробелы в пути.
5. Изменить документ вручную без сохранения: Changed должен отразить изменение, исходный файл не сохраняется.
6. Создать новый несохранённый документ вручную: прототип не должен объявлять его сохранённым.
7. Проверить режим только для чтения. После каждого запуска КОМПАС и документы остаются открытыми; утилита не вызывает диалог сохранения.
8. Сравнить SHA-256 тестовых CAD-файлов до и после запусков без ручного сохранения. Зафиксировать точные версии, JSON, код завершения и любые отклонения.

Снимок нескольких свойств не является транзакцией: пользователь не должен переключать или изменять документ во время чтения. Наличие пути не заменяет будущие проверки существования, прав, актуальности документа и полного набора резервируемых файлов.

## Ручная проверка окна

Окно построено на Walk; запуск в Windows и визуальная проверка не выполнены в среде разработки Linux.

1. Собрать через build.ps1, убедиться, что рядом с EXE находится manifest. Открыть окно без КОМПАС: окно открывается, обновление выводит ошибку подключения.
2. Проверить русские подписи, расположение элементов и длинный путь при масштабах Windows 100%, 150%, 200%; изменить размер окна.
3. Выполнить проверки диагностики выше через кнопку. Для консольных проверок запускать kompaslink-diag.exe.
4. После успешного чтения закрыть документ в КОМПАС и обновить: старый путь и свойства очищаются.
5. Во время чтения кнопка недоступна; окно перемещается и перерисовывается; попытка закрытия сообщает об ожидании. После завершения окно закрывается, КОМПАС остаётся открытым.
6. Сравнить сведения окна с JSON консольной диагностики при неизменном состоянии документа. При отсутствии подтверждённой версии или свойств окно не должно показывать успешное чтение документа.
